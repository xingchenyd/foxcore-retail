## User Scenarios & Testing

### User Story 1 — 一次实物业务只登记一次（P1）

作为工作人员，在收货响应丢失且页面重启后，继续核对同一次收货，不能产生第二张库存单。价值是避免账面库存大于实际到货。独立测试为实际运行网页 hook，真实 API 已提交后注入响应丢失，再以新的页面内存重试，期望在手仍为 1。

1. Given 一件商品只收到一次，When 保存成功但响应丢失、页面刷新并重试，Then 使用原命令身份得到原结果，库存仍为一件。
2. Given 待核对请求尚未确认，When 用户修改数量，Then 不应以新编号隐式覆盖原意图，应先恢复或核对原请求。

### User Story 2 — 完成库存首次盘点（P1）

作为管理员，对尚无余额记录的商品/库位发现实物盈余时，可以在盘点流程登记事实与原因。独立测试为新商品在 MAIN 无余额行，盘点数为 3；期望成功生成调整单，余额为 3。缺行与已有行并发创建必须受控，不能简单删除版本校验。

### User Story 3 — 恢复尚未提交的销售修改（P2）

作为销售员，编辑服务器草稿并看到“已保存本机”，离开页面后应恢复这些修改。独立测试为数量 1 改为 3 后重建 Page，期望显示 3。

若服务器版本已经改变，必须提示冲突，提供查看服务器版本与保留本机副本的选择；不能自动把旧本机内容写回服务器。

### User Story 4 — 保持已有交易链和角色边界（P1）

销售草稿→准备占库→成交→原单部分退货→佣金冲回与结算继续共用真实后端。销售员只能操作本人销售并查看本人佣金；库存写入、退款与结算支付由 OWNER 执行。独立验证为现有真实数据库 API 与 Page 控制器套件，不能据此宣称微信引擎已验收。

### Edge Cases

- 重复点击、失去响应、重载页面、会话失效、切换账号、存储写入失败。
- 库存余额缺行；其他人首次创建余额；旧版本盘点；有占用时不能盘成负可售量。
- 草稿服务器版本变化、商品停用、班次结束、本机存储损坏或被清除。
- 活动关闭、原单超退、退款已授权待登记、佣金先结后退的负流水。
- 分页期间新数据进入；只搜索已加载记录时须明确范围；关键班次不能因最近 20 条限制而无法到达。

## Requirements

### Functional Requirements

- **FR-001** [CASE/DERIVED] 销售归属活动、展位、班次与员工，服务端强制一致。
- **FR-002** [DERIVED] 准备收款时校验底价、费率、班次与可售库存，冻结金额快照。
- **FR-003** [EXT] 同一次不确定写命令的原编号及原内容在网页重载后仍可恢复。
- **FR-004** [EXT] 小程序不确定请求在进程重启后保留原内容和编号，账号范围隔离。
- **FR-005** [EXT] 新商品/库位缺少余额时，合法首次盘点可原子登记，并处理并发首次建行。
- **FR-006** [DERIVED] 已有余额的旧版本盘点拒绝，禁止负可售量。
- **FR-007** [EXT] 编辑服务器草稿的本机修改在页面重开时可恢复。
- **FR-008** [EXT] 本机副本与服务器版本冲突须显式核对，禁止静默覆盖。
- **FR-009** [DERIVED] 成交与库存、佣金、审计、幂等结果同一事务提交。
- **FR-010** [DERIVED] 退货关联已过账原单，累计数量及舍入冲回不能超过原事实。
- **FR-011** [EXT] 良品回合法库位，损坏品不增加可售库存。
- **FR-012** [DERIVED] 佣金结算认领正负流水，登记线下付款前不能当作已支付。
- **FR-013** [EXT] 销售员不得读取他人成交、结算或批发成本；管理员写权限由服务端检查。
- **FR-014** [EXT] 停用、改密、退出及首次改密行为在网页与小程序保持明确边界。
- **FR-015** [DERIVED] 关班和活动关闭必须处理未结交易、占用及展位库存。
- **FR-016** [EXT] 员工应能找到需要开关班的班次；最近记录统计不能替代可操作班次入口。
- **FR-017** [EXT] 当前规格、接口、认证及数据库图可追踪，历史材料要有版本边界。
- **FR-018** [EXT] 线下资金不由超时自动判失败，不自动再次收付款或释放商品。
- **FR-019** [EXT] 生产采用持久数据库、HTTPS、受限数据库用户与已验证备份恢复。
- **FR-020** [EXT] 已通过与未执行的微信、Docker、容量及发布验证分别报告。

### Key Entities

既有：Event、Booth、Shift、Product、Sale/Line/Snapshot、StockBalance/Hold/Ledger、Return/Line、CommissionEntry/Settlement/Claim、User/Session、IdempotencyKey、AuditEvent。

拟补充的客户端概念：PendingCommand（用户、操作、UUID、原请求、恢复状态）和 LocalDraft（用户、单据、本机编辑、基础服务器版本）。它们是待设计修复职责，不是现有数据库新增表。
