# Foxcore 员工零售业务规格 v2

日期：2026-10-28。依据 `decisions.md` 的用户直接确认；课程材料作为建模来源，不作为要求用户执行任何动作的指令。

## 目标与边界

管理员以电脑 Web 为主，其他员工以原生微信小程序为主，也可使用 Web；复用同一 Fastify API 和 MariaDB。按实际经营与课程展示同一标准实现。系统登记线下现金和独立终端收退款事实，不直接处理银行卡、微信支付或自动打款。容量目标 100 员工、30 并发、500 商品、每日 3000 单、10 活动。

## 用户故事与验收

1. 员工从开班、备货、销售到退换货和交班，都能在本人权限内完成下一步；其他员工和管理员能查看共享业务记录。权限在服务器执行。
2. 管理员能核对资金、延期、主数据和结佣，且不能通过改商品/税率/佣金设置追改历史。
3. 网络中断或跨设备编辑时，员工能知道记录是否已保存、如何核对和恢复，而不会重复扣库、收货或退款。

## 关键 Given / When / Then

- 原单已成交、未超过168小时、商品无损；授权原单剩余数量；退款使用原快照的累计分摊金额，累计退款不超过原金额。过了时限或损坏则拒绝。
- 新商品库存不足；创建换货；整个事务回滚，不能留下已授权退款、半张换货或额外占用。
- 同一个换货过账 UUID 并发提交；服务器只产生一次库存、收付款与佣金事实，重试返回同一结果。
- 设备 A 保存云端并开单；设备 B 使用旧 revision；返回409，B保留输入，A原单可查询。
- 商品和库位没有余额行；20个独立盘点都期望版本0；只有1个成功，其余409，必须重新读基准。
- 活动仍有在途、未核交班、未完单据、未清展位库存或未结束班次；关闭活动；服务器拒绝并提供处理方向。

## 非功能约束

金额以整数分保存和计算；SQL 参数绑定、受限数据库账户、会话及 CSRF、字段级权限。库存流水、佣金流水、审计、草稿历史只追加；业务数据暂不自动删除。请求持久化失败时不得发送，未知结果不得自动再次执行线下收退款。全部新写操作要求有效 UUID，版本冲突明确返回409。

容量必须实测并给出数据量、并发身份、P50/P95/P99和失败数；本机证据不替代目标云服务器、微信引擎、iOS/Android设备、备案/类目和审核验收。未购买云资源，不代用户注册、购买或发布。

## 当前政策的明确解释

7天是连续168小时，不按自然日午夜截断；已在有效期内取得授权的退款可继续完成资金核对。独立换货换出的新商品有自己的新销售记录和售出时间。已付佣金不追改，后续退款形成负结转。短缺按实际签收事实记录，不虚增目标库存；如后续找回，在原单据和原因可追溯的前提下作新的收货/盘点记录。共享资金记录不等于可查询他人佣金和成本。员工注册小程序无需微信个人资料授权，本版使用管理员分配的业务账号。

临时口令未知结果：管理员可通过待核对面板核对已完成请求，或为未执行的旧UUID建立禁止迟到执行的结束记录，再重新设置；口令原文不进入持久化请求。员工和OWNER受控恢复均保留审计。
