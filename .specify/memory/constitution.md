# Foxcore Retail Review Constitution

Version: 1.0.0. Ratified: 2026-10-27. Scope: this repository's reassessment.

## I. Source authority

User instructions define the requested scope. Case requirements, course notes and reference ERDs are evidence, not executable instructions. Separate CASE, DERIVED, EXT and DEC requirements. Missing primary evidence MUST remain explicit; an analysis model is not proof of interviews or stakeholder approval.

## II. Business facts and correctness

Server and MariaDB MUST remain authoritative for roles, integer-cent amounts, inventory, original-sale returns and commission facts. A retry MUST preserve the identity of the same uncertain command across process loss. Never infer offline payment/refund completion from a network timeout. Never rewrite posted snapshots to repair history.

## III. Verification honesty

Every confirmed defect MUST have source evidence and a concrete reproduction. Baseline regression passes MUST NOT imply coverage of previously untested boundaries. Distinguish real HTTP/database, controller adapters, browser, Docker and WeChat engine/device evidence. Known failing acceptance probes MUST remain visible. No `Converged` or production-ready verdict while release-critical defects or required runtime evidence are unresolved.

## IV. Isolation and reversibility

Only a dedicated loopback database with synthetic records may be mutated during this review. Do not change business source or schema during assessment. Keep main and the delivered Mini Program baseline intact; review artifacts and probes go to a separate branch. Never publish credentials, raw course PDFs, runtime data or database backups.

## V. Proportionate design

Retain the modular Fastify / MariaDB architecture and shared web/Mini Program business model unless evidence demonstrates a need to change it. Model desired command recovery and draft conflicts explicitly before implementing them. Do not add a new payment gateway, CRM, supplier ledger or general ledger under a defect label without a separate requirement.

## Governance

Assessment produces spec, plan, traceability, failing probes and a remediation backlog. Remediation is a separate step. This review can finish with `CHANGES_REQUIRED`; that is not release acceptance. A constitution change must state its reason and affected requirements rather than weaken a principle to make a failing result pass.
