## 1 引言

### 1.1 目的

本文档面向**最终使用者**，以"界面 + 流程"的方式说明如何使用 Foxcore Retail 完成一次完整的现场零售作业：从系统登录、开场准备、现场成交，到退货、佣金结算与报表核对。

### 1.2 使用约定

- 文档中 `「」` 表示界面上的按钮或链接名称；`【】` 表示页面或标签名称；
- 步骤编号即操作顺序，请勿跳步；
- 涉及**线下动作**（收款、退款、付款、实物交接）的步骤已单独标注，系统不会代替你完成这些动作；
- 本文档中所有金额单位为 **CAD（加元）**，界面按 CAD 显示，系统内部以"分"整数存储。

### 1.3 界面设计原则（摘要）

| 原则 | 在界面上的体现 |
|---|---|
| 角色可见即角色可用 | 销售员不渲染【退货与核对】【操作日志】入口 |
| 服务端为唯一真相 | 页面刷新即从服务端重取，不缓存金额；不保存登录令牌 |
| 错误可定位 | 错误提示附带 `requestId`，可与服务端日志对应 |
| 现场可用性 | 关键按钮尺寸适配移动端；目录类列表每页 20 条、销售列表每页 100 条；选择器上限 100 项 |
| 口径透明 | 报表标注"仅计已过账销售 − 已过账退货"；毛利标注为"标准成本估算" |

## 2 登录与首次设置

### 2.1 首次登录（管理员）

| 步骤 | 操作 | 界面反馈 |
|---|---|---|
| 1 | 浏览器打开 `http://localhost:3000` | 显示登录页：用户名、密码输入框与「登录系统 →」按钮 |
| 2 | 获取初始密码：在本机终端运行 `docker compose exec app cat /run/foxcore-app/owner_initial_password` | 终端输出临时口令（≥32 字符） |
| 3 | 用户名填 `owner`，密码填步骤 2 的临时口令，点击「登录系统 →」 | 进入【运营工作台】；**系统强制要求修改密码** |
| 4 | 设置至少 **16 字符**的个人密码并确认 | 旧会话失效；密码文件在改密成功后自动删除 |
| 5 | 使用新密码重新登录 | 正常进入系统 |

> 注意：**安全提醒**：初始口令只出现在你自己的终端里。请勿将口令粘贴到截图、问题报告、聊天记录或任何压缩包中。

### 2.2 登录页字段

| 字段 | 说明 |
|---|---|
| 用户名 | 管理员默认 `owner`；销售员账号由管理员在【人员与班次】发放 |
| 密码 | 区分大小写；连续失败会触发临时锁定（等待若干分钟后自动解锁） |
| 会话有效期 | 登录后 **12 小时**绝对过期；**30 分钟**无操作自动登出 |

### 2.3 销售员账号

管理员在【人员与班次】中为员工创建账号：一名员工档案**只能关联一个**登录账号；停用账号不会删除其历史单据。

## 4 核心操作流程

### 4.1 流程 A：开场准备

**目标**：让一个活动具备可销售条件（活动开放、展位就位、货品到位、班次开始）。

| 步骤 | 页面 | 操作 | 说明/校验 |
|---|---|---|---|
| A-1 | 【活动与展位】 | 录入场地（名称、街道、城市、省份、邮编） | 地址按字段分别录入，界面组合显示完整地址 |
| A-2 | 【活动与展位】 | 创建活动：选择场地与类别、填写名称与起止日期、税率（bps）、勾选政策确认 | `结束日期 ≥ 开始日期`；税率 ≤ 10000 bps（即 100%） |
| A-3 | 【活动与展位】 | 为该活动至少建立一个展位 | **无展位的活动不能开放** |
| A-4 | 【活动与展位】 | 点击「开放活动」 | 状态变为 OPEN |
| A-5 | 【商品】 | 录入 SKU、名称、批发成本、最低成交价、建议价 | 建议价不得低于最低成交价 |
| A-6 | 【人员与班次】 | 建立员工档案（姓名、可选地址与电话、佣金率） | 佣金率 ≤ 10000 bps |
| A-7 | 【人员与班次】 | 为员工创建账号（用户名 + 初始密码） | 一名员工仅一个账号 |
| A-8 | 【人员与班次】 | 排班：选择员工、展位、业务日期与计划时段 | 时段须包含 UTC 偏移；业务日期按**多伦多时间**计算 |
| A-9 | 【库存】 | 收货：选择商品与数量，货物入**主仓** | 需填写理由 |
| A-10 | 【库存】 | 调拨：主仓 → 展位库位，填写数量与理由 | **实物交接完成后**再在系统中确认 |
| A-11 | 【人员与班次】 | 到班次时间后开班 | 销售员只能操作**本人**进行中的班次 |

> **可售量说明**：界面显示的可售量 = `在手量 − 已占用量`。已被"准备收款"的单据占用的货品不计入可售。

### 4.2 流程 B：现场成交

**目标**：录入一笔销售并完成过账。

| 步骤 | 页面 | 操作 | 说明/校验 |
|---|---|---|---|
| B-1 | 【销售工作台】 | 点击「新建销售草稿」，选择进行中的班次 | 仅本人进行中的班次可选 |
| B-2 | 【销售工作台】 | 选择商品、数量，填写与顾客商定的 CAD 单价 | 单价可高于底价；低于底价会在下一步被拒 |
| B-3 | 【销售工作台】 | 保存草稿 | 状态 `DRAFT`；此时**不占用库存** |
| B-4 | 【销售工作台】 | 点击「准备收款」 | 系统重新核对：底价、活动状态、税率、佣金率、展位可售量；通过后**占用**商品（状态 `CHECKOUT`） |
| B-5 | **线下动作** | 按界面显示的固定应收额向顾客收款（现金或刷卡终端） | 系统**不会**发起任何银行卡扣款 |
| B-6 | 【销售工作台】 | 登记现金实收额或终端参考号，点击「确认成交」 | 库存 `在手` 与 `占用` 同量下降；生成库存流水、佣金计提、成交时间与审计记录 |
| B-7 | 【销售工作台】 | 使用"上一页/下一页"查询最近单据 | 每页 20 笔 |

> 注意：**响应不明时怎么办**：若点击「确认成交」后网络中断或结果未知，**先查询该单据状态**，确认未过账后再用**同一请求**重试。**不要**再次向顾客收款——重复收款在系统外发生，系统无法为你撤销。

**草稿处理规则**

| 状态 | 可否取消 | 说明 |
|---|---|---|
| `DRAFT` | 可以 | 直接取消，释放无占用 |
| `CHECKOUT` | 可以，但需确认 | 必须先确认款项与商品去向后再取消，占用随之释放 |
| `POSTED` | **不可以** | 已成交单据只能通过【退货与核对】更正，不能删除 |

### 4.3 流程 C：退货与核对（仅管理员）

| 步骤 | 页面 | 操作 | 说明/校验 |
|---|---|---|---|
| C-1 | 【退货与核对】 | 选择原已成交单据 | 仅已过账单据可退 |
| C-2 | 【退货与核对】 | 选择退货行，填写退货数量与理由 | 同一退货单中，原单的每一行只能出现一次 |
| C-3 | 【退货与核对】 | 选择处置方式：`RESTOCK`（良品）或 `DAMAGED`（损坏） | 良品需指定回库库位；损坏品**不计入可售** |
| C-4 | 【退货与核对】 | 点击「授权」 | 系统按累计退货量分摊原单税额与佣金，显示退款额 |
| C-5 | **线下动作** | 按授权金额向顾客退款 | 系统不触发任何退款渠道 |
| C-6 | 【退货与核对】 | 登记退款参考号，点击「过账」 | 生成负向佣金计提；良品生成回库流水 |
| C-7 | — | 校验 | 累计退货数量**超过原销量**会被拒绝（409） |

### 4.4 流程 D：佣金结算（仅管理员）

| 步骤 | 页面 | 操作 | 说明 |
|---|---|---|---|
| D-1 | 【佣金】 | 选择销售员，查看其计提明细 | 销售为正、退货为负 |
| D-2 | 【佣金】 | 点击「准备结算」 | 系统**占用**该员工当前全部未结正负流水 |
| D-3 | 【佣金】 | 核对结算金额与明细 | 结算金额 = 明细合计 |
| D-4 | **线下动作** | 通过公司既有方式向员工付款 | 系统不执行转账 |
| D-5 | 【佣金】 | 登记付款参考号 | 状态 `PREPARED → PAID` |
| D-6 | 【佣金】 | 尚未付款时可「取消准备」 | 释放占用，流水回到未结状态 |

### 4.5 流程 E：报表与导出

| 步骤 | 页面 | 操作 | 说明 |
|---|---|---|---|
| E-1 | 【报表】 | 选择维度：活动 / 商品 / 销售员 | 维度为白名单，不接受任意字段 |
| E-2 | 【报表】 | 查看汇总 | 口径：**已过账销售 − 已过账退货** |
| E-3 | 【报表】 | 点击「导出 CSV」 | 仅管理员可用；文件名 `foxcore-report.csv` |

> **毛利口径**：报表中的毛利为**商品标准成本估算**（成交价 − 成交时冻结的成本），**不含**活动费、差旅与工资，且销售员角色不可见。

### 4.6 流程 F：异常处置

| 步骤 | 操作 |
|---|---|
| F-1 | 发现余额异常时，**立即停止新的交易** |
| F-2 | 备份当前数据卷（见 [07 部署运维](07-deployment-local.md)） |
| F-3 | 执行 `npm run db:check` 排查 16 项不变量 |
| F-4 | 携带 `requestId` 与不变量输出定位问题；必要时从受控备份恢复 |

## 6 常见提示与处置

| 提示 | 含义 | 处置 |
|---|---|---|
| 库存不足 / 已被占用 | 展位可售量不足 | 查看展位可售量与待收款单据；确认是否需要实物调拨 |
| 商品低于最低价 | 商定单价低于商品底价 | 提高单价，或由管理员调整商品底价后重新「准备收款」 |
| 班次不能开/关 | 活动未开放、时间不符或有未处理单据 | 检查活动状态、当前时间与该班次的待处理销售 |
| 幂等键冲突（409） | 同一个幂等键提交了不同内容 | 原键只用于重试**相同**请求；新动作应生成新键 |
| 记录已变化 | 服务端版本与本地不一致 | 刷新页面，重新核对版本、余额与金额后再操作 |
| 累计退货超过原销量 | 退货量超出原单 | 核对原单数量与历史退货，调整退货数量 |
| 403 权限不足 | 当前角色无权访问 | 确认是否使用了正确的账号；销售员不可访问管理接口 |
| 会话已过期 | 超过 12 小时或空闲 30 分钟 | 重新登录 |

## 7 操作禁忌清单

| 编号 | 禁止 | 原因 |
|---|---|---|
| DON-01 | 不要删除已成交单据 | 历史不可篡改；应使用退货流程更正 |
| DON-02 | 不要用同一幂等键提交不同请求 | 会被拒绝（409），且造成排查困难 |
| DON-03 | 不要在响应不明时重复收款 | 系统无法撤销系统外的收款 |
| DON-04 | 不要在未实物交接前确认调拨 | 会造成账面与实物不符 |
| DON-05 | 不要执行 `docker compose down -v` | 会删除持久数据卷 |
| DON-06 | 不要把初始密码、备份文件放入截图或分发包 | 凭据泄露风险 |
| DON-07 | 不要在生产/演示库执行 `npm run seed:sample` | 会写入合成业务数据 |
| DON-08 | 不要手动修改已应用的迁移文件 | 校验和不一致将导致拒绝启动 |

## 附录：字段与格式说明

| 字段 | 格式 | 示例 | 说明 |
|---|---|---|---|
| 税率 / 佣金率 | bps（万分之一） | `1300` = 13% | 上限 10000 |
| 金额输入 | CAD 十进制字符串 | `12.34` | 系统内部以整数分存储 |
| 金额输出（API） | 整数分字符串 | `"1130"` | 界面按 CAD 格式化显示，即 11.30 CAD |
| 时间输入 | 含 UTC 偏移的 ISO 时间 | `2026-09-27T09:00:00.000-04:00` | 业务日期按多伦多时区计算 |
| 业务日期 | 日期 | `2026-09-27` | 班次归属日 |
| SKU | 字符串 | `INT-a1b2c3d4` | 全表唯一 |
| 幂等键 | UUID | `3f2a…` | 每次新业务动作生成一个 |
| 理由 / 备注 | 文本 | — | 库存单据理由**必填** |

> **金额示例**：成交单价 10.00 CAD（1000 分）、税率 1300 bps 时，税额 = 1000 × 13% = 130 分，合计 `1130` 分 = **11.30 CAD**（与 [05 STD TC-009](05-STD.md) 一致）。界面一律按 CAD 格式化显示。
