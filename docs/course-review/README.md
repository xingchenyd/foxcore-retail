日期：2026-10-24。审查基线：`3393bc3a4989b642f881cc891dc305cfda37ee5a`。本次在独立分支 `codex/retail-review-ui-docs-20261024` 交付，不合并或覆盖 main；不代表线上服务已部署。

## 审查结论

项目已经具有现场零售教学系统的主要业务闭环，不是仅有页面的原型。活动、展位、商品、班次、库存占用、销售过账、原单关联退货、佣金冲回与结算、角色权限、幂等和审计均有真实实现。最需要改进的是文档与实现的一致性、操作引导、失败恢复与证据管理。它仍不适合被描述为已经完成生产级 ERP 验收。

当前迁移实际创建 **25 张业务表**，迁移器另建 `schema_migrations`，新数据库共 **26 张表**。源码和 OpenAPI 共 **48 个路径、58 个方法操作**，其中 56 个业务 API 方法、2 个健康检查方法。业务不变量是原 16 项加后续修复 3 项，共 19 项。

结构是按业务能力划分的 Fastify 模块化单体，路由内执行参数化 SQL 与事务脚本。分析类图给出概念、属性与职责，不能等同于已有的 TypeScript 聚合/仓储类。数据库保存整数分，费率为 bps，API ID 与大金额采用字符串。线下支付只有确认记录，无支付网关调用。

## 本次已完成的修正

| 发现的问题 | 本次变化 | 对业务的作用 |
|---|---|---|
| 非法日历日期可能落到数据库并报内部错误 | 在活动创建前校验真实公历日期与数据库日期范围 | 直接给出输入错误，不产生错误活动 |
| 销售列表宽松转换分页参数且没有总数 | 统一严格分页与 count/items 一致快照，保留本人数据范围 | 列表能可靠翻页，非法参数返回 400 |
| 首次登录待改密账号无法退出 | 保留 CSRF 检查，允许安全撤销会话 | 用户可以退出并换账号 |
| 移动端隐藏整个账户区 | 手机也可看到账号与退出入口 | 不再陷入无法退出的页面 |
| 操作中可重复点击、保存和失败提示不清 | 同步锁定正在提交的动作，显示状态和错误 | 减少重复操作和对请求结果的误判 |
| 销售录入缺少步骤、金额预估及找零提示 | 明确草稿、准备、确认三个阶段，整数分预估 | 金额录入有反馈，准备后的服务端快照仍为权威 |
| 记录多时难找、菜单与业务顺序脱节 | 已加载记录搜索、状态筛选、流程引导与快捷入口 | 找记录及判断下一步更直接 |
| 加载前指标显示 0，可能被理解为真实业绩 | 使用加载/错误状态，明确最近记录范围 | 不把未取到数据当成零业绩 |
| 旧文档及图纸表数、继承、FK、审计机制失真 | 新图源、图册、字段字典和课程映射，修正四份主文档 | 图—规约—SQL—代码更容易相互核对 |
| 锁定依赖检出 7 项审计问题 | 对 Fastify、Vite、Vitest、concurrently 及相关依赖做兼容补丁升级 | 当前 npm audit 为 0；不代表没有未知安全风险 |

## 重建图纸与阅读顺序

1. `python scripts/generate-course-diagrams.py` 依据受版本控制的规则与 SQL 生成图源和数据字典。
2. 使用 Java 与 PlantUML 1.2026.2：`java -jar plantuml.jar -charset UTF-8 -tsvg "docs/course-review/diagrams/*.puml"`。PNG 将 `-tsvg` 改为 `-tpng`。生成器使用 Smetana 布局，不依赖外部 Graphviz。
3. 先读本审查结论与课程映射，再看上下文、业务图与用例图，再看类图/状态/序列，最后对照 ERD、字典、代码与验证结果。
4. 总 ERD 是可放大总览；打印或讲解优先使用六张分域图。所有图都是本次重新生成，旧目录图片仅作历史参考。
