## 关键行为的具体含义

- 并发库存验证是 20 个请求争用最后 1 件，结果 1 个成功、19 个冲突。它不是系统吞吐或 p95 延迟基准。
- 同键过账验证是 20 个请求得到同一业务结果；不会因此声明不同幂等键的误操作能被系统自动识别。
- 原生 HTTP 适配器只存在于本轮私有工作目录，每次核对固定工作区、新数据目录、随机库名及实例身份；原仓库 Docker 验证器保护未被删除或伪造。
- 页面金额预估只帮助录入；准备收款时服务端的价格、税额、佣金快照与库存校验仍是最终依据。
- 工作台显示最近 100 条销售/班次记录的指标，金额含税且未扣退货；经营净额应看报表。截图中的数量与金额属于合成测试数据，不是企业真实业绩。

## 可复现入口

源码使用 Node 24。先执行 `npm ci`，再执行 `npm run verify:static`。完整环境应启动 Docker 并按仓库说明执行 `npm run verify:full`；该命令创建独立一次性实例，不应改为指向用户的真实业务库。

本轮前端回归使用原 `playwright.config.ts` 的 desktop / mobile 两个项目，凭据只由本机私有文件传入，未放进源码、报告、截图或交付包。原生方式的运行器、数据库、会话、原始浏览器 trace、临时口令与服务日志也不属于交付物。交付只保留脱敏的结果摘要、静态日志、SQL 核查结果和合成数据截图。
