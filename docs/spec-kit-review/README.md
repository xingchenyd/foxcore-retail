## 重建设计与当前实现比较

| 维度 | 当前实现 | 规格要求 / 修复方向 |
|---|---|---|
| 业务架构 | 模块化单体，共用 Fastify/MariaDB | 保留；没有证据支持全量重写或换库 |
| 钱、库存、权限 | 整数分、事务、范围授权、流水审计已有实现 | 保留并继续回归 |
| 网页不确定命令 | UUID 保存在内存；刷新丢失 | 用户隔离耐久收件箱，写前持久化与原编号核对 |
| 小程序命令恢复 | 写前存储、原体原键、重启恢复 | 对照测试通过；真机持久性仍待验收 |
| 首次盘点 | 缺行 0 / 新行 1 | 明确缺行并发前提，不能删除版本校验 |
| 已有草稿恢复 | 写本机但 load 走服务器分支 | baseVersion 校验与冲突提示，不能无条件覆盖服务器 |
| 需求/图/合同 | 有大量既有材料，也有历史入口漂移 | 当前版本统一追踪，历史图注明时间 |
| 经营制度 | 线下收退款与佣金事实记录 | 现金日结、损坏实物、负佣金追偿须另定规则 |

模型和合同见 [data-model.md](../../specs/001-retail-reassessment/data-model.md)、[recovery.md](../../specs/001-retail-reassessment/contracts/recovery.md)。未增加第二份业务库，未复制参考 ERD 的专有字段。

当前预期退出码为 **1**，因为三个真实缺陷尚未修复。小程序本机草稿用例是控制器和固定响应；其他库存/重试用例连接真实 MariaDB。网页用例执行真实 hook 源码，VM 重建模拟页面重载，并非浏览器渲染端到端证据。
