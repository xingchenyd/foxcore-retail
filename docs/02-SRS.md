## 功能需求

- **FR-01 主数据**：OWNER 创建场地、活动、展位、商品、员工；SKU 与展位位置唯一。已过账关联的主数据保留历史，不级联删除。
- **FR-02 排班**：同一员工的计划时段不能重叠，相邻半开区间允许；开班需活动已开放且当前时间在时段内。SALESPERSON 只见自己的班次。
- **FR-03 库存**：主仓接收、确认实物交接后的调拨、按版本盘点调整；`available = on_hand - reserved`，不得为负。
- **FR-04 销售**：草稿可编辑；准备收款复查商品、底价、税率、佣金率及展位可售量，冻结快照并占用库存；成交需登记线下收款，原子扣实物并计提佣金；未成交单可按核对要求取消。
- **FR-05 退货**：仅 OWNER 对原已过账单建立退货，先授权数量和退款额，再凭线下退款依据过账；良品入库，损坏品不回可售。
- **FR-06 佣金**：按销售员正负流水计提；准备结算自动占用所有未结流水，正余额方可支付登记；取消未付款结算释放占用。
- **FR-07 报表**：按活动、商品、员工汇总已过账销售与退货，税前净额、税额、净数量、佣金、标准成本毛利估计；CSV 仅 OWNER 可导出。
- **FR-08 安全与审计**：仅管理员发账户；随机服务端会话、Argon2id、HttpOnly Cookie、CSRF、角色范围；关键命令写审计和幂等结果。

## 规则和非功能需求

- **DEC-01** 业务日期按 `America/Toronto`，操作时间以 UTC 保存。计划时段输入须带 UTC 偏移，避免夏令时静默猜测。
- **DEC-02** CAD 金额输入为十进制字符串，最多两位小数；库中整数分，内部 bigint 运算。数量为正整数，一单最多 100 行。
- **DEC-03** 税前行额 = 数量 × 最终单位价；税与佣金分别按 bps 做整数 half-up。底价在准备收款时重新校验。
- **DEC-04** 现金实收不低于应收；外部终端必须有参考号。系统只记录人工确认，不验证银行收单。
- **NFR-01** 浏览器端与 API 同源；数据库真实持久化，应用重启不重置交易。
- **NFR-02** 写命令需 UUID 幂等键；同键同体重试得同结果，异体冲突；库存、退款、佣金须在事务内核对。
- **NFR-03** API 禁止泄露密码、会话、SQL 详情。销售员不可查看批发成本、他人销售及全局审计。
- **NFR-04** 界面含加载、空结果、失败、状态与成功反馈，支持桌面与手机完成关键操作。

## 用例规约

| 用例 | 触发者/前置 | 主成功过程（人 → 系统） | 异常与恢复 / 后置 |
|---|---|---|---|
| UC-01 管理活动展位 | OWNER 已登录 | 填场地/活动 → 校验日期与类别 → 建展位 → 确认税务口径并开放 | 无展位/未确认税率返回 409；开放后可排班 |
| UC-02 维护商品员工 | OWNER | 填 SKU、成本、底价及员工信息 → 唯一校验并保存 | 重复 SKU 409；历史快照不随主数据改变 |
| UC-03 安排和开始/结束班次 | OWNER 排班；本人或 OWNER 开关班 | 选员工/展位/带偏移时段 → 查重叠 → 到时开班 → 处理未结单后关班 | 重叠或活动未开放 409；未结账不许关班 |
| UC-04 接收/调拨/盘点库存 | OWNER | 输入数量、依据及库位 → 锁余额 → 写单据和流水 | 库存不足或旧版本盘点 409；余额与流水一致 |
| UC-05 录销售草稿 | 当前有效班次的销售员或 OWNER | 选商品、数量、协商价 → 保存草稿 | 非本人班次 404；无效数量 400；不扣库存 |
| UC-06 准备收款 | 草稿版本有效 | 点准备 → 服务器核价、费率和库存 → 冻结金额、占用库存 | 底价不足/并发最后一件 409；失败不占用 |
| UC-07 确认成交 | CHECKOUT 已线下收款 | 登记现金或终端参考 → 原子写成交、库存、佣金、审计 → 出凭证 | 响应不明先查单据/原键重试；不得再次收款 |
| UC-08 取消/核对收款 | DRAFT 或 CHECKOUT | OWNER 核对付款和商品去向 → 填原因 → 释放占用并取消 | 已交付不可取消，应按原单过账后退货 |
| UC-09 办退货/更正 | OWNER；原单 POSTED | 建退货明细 → 系统授权数量与金额 → 人工退款 → 登记凭证并入库/冲佣 | 重复授权、超数量 409；支付结果不明保持授权待核对 |
| UC-10 佣金结算 | OWNER | 选员工 → 系统占用全部未结正负流水 → 人工支付 → 登记参考 | 净额非正或已有 PREPARED 409；不确定时不重付 |
| UC-11 查询导出报表 | 登录；CSV 需 OWNER | 选维度 → 服务端聚合过账事实 → 显示/导出 | 销售员限定本人；不把草稿算收入 |
| UC-12 账户/审计 | OWNER | 发放一次性临时密码、查看审计、停用账号 | 最后 OWNER 不可停用；停用即撤销会话 |

## 用例详细规约

以下编号与上表、[STD 验收编号](05-STD.md) 对应。所有业务写入要求有效会话、CSRF 和 UUID 幂等键；业务动作与审计在同一事务提交。`404` 可用于隐藏非本人资源。

### UC-01 管理活动与展位

- **角色/前置**：OWNER 已登录，已明确活动当地日期及税务口径。
- **人→系统**：录入场地地址与说明→保存 VENUE；选七类 CATEGORY、日期和场地→系统校验并建 DRAFT EVENT；录入展位位置→系统核查同活动位置唯一并建 BOOTH；点击开放→系统复查至少一个有效展位及税率确认。
- **后置/数据**：活动 OPEN，可用于排班；`events.venue_id/category_id` 与 `booths.event_id` 有 FK。无展位或税率未确认保持 DRAFT 并报 409。验证 AT-03。

### UC-02 维护商品、员工和账户

- **角色/前置**：OWNER 已登录，掌握真实 SKU、成本、底价和员工资料。
- **人→系统**：录商品→系统校验 SKU、成本和价格后保存；录员工姓名、地址、电话和佣金率→系统建档；指定员工并发 16 字符以上临时密码→系统创建 SALESPERSON 账号。
- **后置/异常**：重复 SKU、重复账号或无效费率拒绝；员工账号首次登录须改密，已过账交易保留原快照。商品可按版本更新并停用；账户可停用且撤销会话，最后 OWNER 不能停用。验证 AT-03、AT-10。

### UC-03 排班、开班和关班

- **角色/前置**：OWNER 建班；本人销售员或 OWNER 开关班。活动和展位存在。
- **人→系统**：提交员工、展位、带 UTC 偏移的时段→系统换算当地业务日期、排除重叠并存 PLANNED；到时点击开班→系统确认活动 OPEN 与当前时刻在半开时段内；营业后处理草稿/待收款单，点击关班。
- **后置/异常**：一班一展位、员工可有多班；重叠/未开放/未到时或仍有未结销售返回 409，班次状态不变。验证 AT-03、AT-05。

### UC-04 收货、调拨和盘点

- **角色/前置**：OWNER，商品及库位已存在；调拨时实物已交接。
- **人→系统**：输入收货数量与依据→主仓增加；选择来源/目的地并确认交接→系统锁两端余额、核可售量、写两边流水；盘点时输入实际数量、读到的余额版本和原因→系统计算差额并写调整流水。
- **后置/异常**：`on_hand >= reserved >= 0`，余额等于历史流水和；未确认交接、库存不足或旧版本拒绝，整单回滚。验证 AT-04、AT-07、AT-12。

### UC-05 录入销售草稿

- **角色/前置**：OWNER 或班次本人，班次 ACTIVE、活动 OPEN。
- **人→系统**：选班次，添加 1–100 行商品、正整数数量和十进制 CAD 协商价→系统核权限和格式并保存 DRAFT；可用版本更新未准备草稿。
- **后置/异常**：草稿关联原活动与班次，不扣库存；非本人班次隐藏，重复行/无效金额拒绝。验证 AT-05、AT-10。

### UC-06 准备收款

- **角色/前置**：有权访问且版本未变的 DRAFT。
- **人→系统**：点击准备→系统重读活动、班次、商品底价、税率、佣金率和展位可售量；按整数分/half-up 算额，冻结行快照并建立 hold。
- **后置/异常**：状态 CHECKOUT，`reserved` 增加而 `on_hand` 不变；价格不足、库存争用或旧版本返回 409，失败无 hold。验证 AT-05、AT-07。

### UC-07 确认成交

- **角色/前置**：有权访问的 CHECKOUT，线下收款已实际完成，商品尚未重复交付。
- **人→系统**：核对固定应收；现金输入实收额或终端输入外部参考号→系统在同一事务扣在手及占用、记库存负流水、销售时间/单号与正佣金流水，返回成交凭证。
- **后置/异常**：POSTED 不可编辑；现金不足/终端缺参考拒绝。同键同体重试返回原结果，同键异体 409；响应不明先查单或原键重试，不二次收款。验证 AT-05、AT-06。

### UC-08 取消与核对待成交单

- **角色/前置**：本人或 OWNER 可取消 DRAFT；CHECKOUT 仅 OWNER，须确认收款和货物去向。
- **人→系统**：填原因；CHECKOUT 另确认付款已核对且商品未交付或已收回→系统释放 hold 和 reserved，再将单据置 CANCELLED 并审计。
- **后置/异常**：POSTED 不能取消；缺核对确认拒绝且保留占用，须走退货更正。验证 AT-05、AT-06。

### UC-09 退货与更正

- **角色/前置**：OWNER，原单 POSTED，已核对退货行及良品/损坏品去向。
- **人→系统**：建 DRAFT RETURN→系统按原行及累计已退量授权，并按累计比例分摊税/佣金；人工执行退款→登记退款参考后 POSTED，良品入指定库位、损坏品不入可售，并写负佣金。
- **后置/异常**：原销售不删除；同一原单只有一个待授权退款；超原量、重复授权返回 409。付款结果不明先保持 AUTHORIZED 待核对，取消需确认退款未执行/已撤销。验证 AT-08。

### UC-10 佣金结算

- **角色/前置**：OWNER，员工有正的未结净佣金，线下支付未执行。
- **人→系统**：选择员工→系统锁其全部未结正负流水并建 PREPARED，汇总支付额；人工付款后登记外部参考→PAID。若未付款，可输入原因并核对后取消，释放占用。
- **后置/异常**：同一流水只被一个有效结算占用；净额非正/已有 PREPARED/重复支付拒绝。退款后的负佣金保留待下次结算。验证 AT-09、AT-12。

### UC-11 查询与导出报表

- **角色/前置**：已登录；CSV 仅 OWNER。
- **人→系统**：选活动、商品或员工维度→系统从 POSTED 销售和 POSTED 退货聚合净数量、税前额、税额、佣金及标准成本毛利估计；OWNER 可导出 CSV。
- **后置/异常**：销售员查询限定本人，不能读批发成本；CSV 的文本防公式注入。草稿和待收款单不算收入。验证 AT-10、AT-11。

### UC-12 账户与审计

- **角色/前置**：OWNER 管账号和看全局审计；每个登录用户可改自身密码。
- **人→系统**：OWNER 创建员工账号或停用账号→系统撤销旧会话；用户改密→旧会话撤销；管理员查看带时间、操作者及对象的关键事件。
- **后置/异常**：最后 OWNER 不可停用；密码只存 Argon2id 散列，Cookie 只含随机会话令牌。审计不可由运行账号更新/删除。验证 AT-02、AT-10。
