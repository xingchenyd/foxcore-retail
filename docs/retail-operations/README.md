## 业务如何衔接

1. OWNER建活动、确认真实适用税率、建展位、商品和员工班次；CNY活动使用北京时间和含税成交价。先确认税务口径才开放，系统不自行假设13%。
2. 员工到岗录入备用金开班。收货进入MAIN；调拨发出进入在途，另一操作员清点后签收，良品才成为展位可售库存。损坏转隔离库，短缺单独记因。
3. 销售先录入，草稿不占库；准备时冻结金额/税/佣金快照并占库；线下收款后确认过账。待收款取消须核对资金和商品，保留原记录。
4. 无损退换货必须关联原成交单，在168小时内授权。退货用原快照累计分摊，现金退款归实际办理班次。换货独立准备，差价可补收或退还；原子过账同时完成退入、新品扣库和两位员工的佣金方向。
5. 处理完未结销售后提交现金交班，系统显示应交、员工填实交和原因；OWNER核对。交班后可关班；活动所有库存、在途、单据、班次和交班均满足条件后关闭，才能结佣。付款后退货产生负流水，留待抵扣后续佣金。
6. 编辑内容可存云端，在同一业务账号的另一设备载入；冲突保留输入。保存为单据时消耗工作区版本，另一设备旧副本不能再次开单。网络未知结果使用原操作编号核对，不能再次执行线下收退款。

## 异常、恢复与兼容

上次三个复现问题已修复：网页丢响应后重载重试不重复收货；首次缺行盘点可使用版本0；已有草稿重进可恢复兼容本机副本，服务器版本变化则提示冲突。新增保护覆盖跨标签页互斥、存储失败、账号隔离、口令不落请求明文、换货库存不足回滚、重复签收拒绝、现金归属和负佣金结转。

## 复现入口

使用Node24，先`npm ci`。静态：`npm run verify:static`。隔离测试服务启动并私下配置TEST_BASE_URL（仅loopback）、TEST_CONFIRM=yes、TEST_OWNER_PASSWORD后，执行`npm run test:integration`和`npm run test:review`；容量另用`npm run test:capacity`。这些测试会创建合成数据，只在专用空库或隔离库运行。Docker独立完整验收入口仍为`npm run verify:full`，本机未通过该门禁不标记为通过。图纸可由PlantUML重新渲染，结构JSON不包含业务数据。
