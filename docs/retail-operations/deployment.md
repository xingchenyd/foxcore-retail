# 从零部署、微信账号与交接步骤

本指南对应2026-10-28代码，给第一次接触小程序的使用者。当前交付只完成代码、本机验证和导入包；没有替你注册微信主体、购买服务器、发布或覆盖main。下列步骤按先后进行，账号与扫码步骤由你本人完成。微信后台的菜单和类目可能调整，以登录后的实际页面为准。

## 先分清三个东西

| 名称 | 用途 | 谁提供 |
|---|---|---|
| 小程序AppID | 微信识别这个小程序的编号 | 你注册小程序后在后台取得 |
| 服务器与HTTPS域名 | 保存业务数据、给电脑和手机提供同一个API | 你以后选择云资源和域名，本项目负责业务服务 |
| 员工业务账号 | 员工进入Foxcore并决定权限 | OWNER在网页创建，首次登录改密 |

本版使用员工业务账号，不依赖微信openid或微信支付。AppID不是密码；AppSecret等密钥不应放进小程序、GitHub或聊天。你目前没有小程序账号，也可以先运行网页和查看本机页面适配器。

## 一、拿到这一版代码

1. 在GitHub打开交付分支`codex/retail-operations-20261028`，确认分支名后使用“Code / Download ZIP”，或使用交付的完整源码包。不要选择main下载旧网页版本。
2. 解压到一个容易找到的文件夹，例如`C:\Foxcore`。文件夹里应能看到`package.json`、`compose.yaml`、`apps`和`docs`。
3. 安装Node.js 24，重开终端，在该文件夹执行`node --version`，应显示v24。然后执行`npm ci`。这一步安装项目依赖，不要求微信账号。
4. 先读本目录的`README.md`、`verification.json`和`index.html`。源码包不带数据库密码、真实员工数据或数据库备份；不要把旧测试库当作正式经营库。

## 二、先在电脑运行后端和网页

已有熟悉的运维环境可按`docs/07-deployment-local.md`配置；第一次可采用项目现有Docker Compose方式。Docker实际运行在本机仍是未完成的目标环境门禁，以下为待执行步骤。

1. 安装官方Docker Desktop，按安装器提示启用所需虚拟化/WSL功能并重启。启动Docker Desktop，待服务就绪后执行`docker version`和`docker compose version`。必须同时看到客户端和服务器可用。
2. 在源码根目录执行`docker compose up -d --build`。它将创建专属数据库卷，依次启动数据库、运行001-005迁移和应用。首次下载和构建可能较久。
3. 执行`docker compose ps`，检查数据库健康、迁移成功、应用运行；浏览器打开`http://localhost:3000`。若未成功，先查看`docker compose logs --tail=100 app migrate db`，不要通过反复删数据库卷解决。
4. 初始管理员用户名为`owner`。在你自己的终端执行`docker compose exec app cat /run/foxcore-app/owner_initial_password`读取初始口令，立即登录并修改个人口令。该输出只供本人使用。
5. 在网页依次创建场地、活动、展位、商品、员工、账号和班次。中国活动按含税价录入；由你按实际纳税身份确认税率，未确认不能开放。创建员工账号时分配一次性临时口令，员工首次登录改密。
6. 用少量虚拟数据试一遍：开班及备用金→收货→业务中心发出调拨→清点签收→销售草稿→准备收款→确认线下收款→原单退货/独立换货→现金交班→管理员核对→退回剩余库存→关班→活动关闭→结佣。测试资金只登记虚拟事实，不实际收付款。

## 三、没有微信账号时怎么预览

源码检查使用`npm run typecheck`和`npm run build`，会得到14页原生小程序构建目录`apps/miniprogram/build`。默认AppID为游客占位、API为空，不能据此声称微信编译或真机通过。

还可以使用开发用的浏览器适配器检查真实WXML和控制器。后端在本机3000端口运行时，在源码根目录执行：

```powershell
node scripts/build-miniprogram.mjs --api http://127.0.0.1:8021 --development
npm run mini:preview
```

打开终端提示的`http://127.0.0.1:8021`，用你在网页创建的员工业务账号登录。适配器只用于开发，不能代替微信开发者工具、手机渲染、扫码、真机网络和审核。它不应部署为正式小程序。

## 四、以后注册微信小程序

1. 进入[微信公众平台](https://mp.weixin.qq.com/)，注册“小程序”。准备自己可用的邮箱和本人微信，按后台选择主体和填写资料；身份核验、协议、扫码等由你完成。
2. 你目前倾向个人主体。正式注册或发布前，先在后台确认你实际经营内容允许使用的服务类目、主体和备案要求，不用不相符的工具类目绕过限制。员工内部使用和正式发布的能力，以微信当前规则为准。
3. 注册后在后台的开发管理/开发设置附近找到AppID，形如`wx`开头的编号。后续适配只需AppID；不要发送AppSecret、微信密码、身份证或扫码凭证。
4. 从[微信官方开发者工具下载页](https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html)安装稳定版，打开后本人扫码登录。把自己的微信设为该小程序管理员或开发者；其他体验人员按后台成员管理添加。

## 五、选购服务器前先做什么

你尚未购买腾讯云。19.9元价格不能说明CPU、内存、磁盘、流量、续费、地域或备案资格，也不能证明能承载30人并发。先确定这些配置，再把本项目的容量脚本放到目标测试环境重跑，确认延迟、错误率、内存、磁盘和备份恢复。

中国内地服务器对外使用域名时，应提前按腾讯云和实际主管要求办理备案。腾讯云的[轻量服务器备案说明](https://cloud.tencent.cn/document/product/1207/45756)包含域名、实名和云资源有效期条件；购买前以该页和控制台最新条件核对。服务器和域名注册、实名、购买、备案资料与付款由你完成。

## 六、把同一后端部署到云端

1. 在目标服务器创建正式专属目录和数据库卷，保存部署前快照；使用Linux受支持系统、Node24构建或现有Docker镜像流程。不要把开发测试数据导入正式账。
2. 通过现有Compose部署应用和私网数据库。数据库不要开放公网3306端口；应用只通过同源HTTPS反向代理提供服务。
3. 将域名解析到服务器，在反向代理配置有效HTTPS证书；上游指向应用3000端口。应用设置`APP_ENV=production`、`PUBLIC_ORIGIN=https://你的真实域名`、`COOKIE_SECURE=true`，反向代理正确转发请求。数据库密码放私有环境或Secret文件，不进仓库。
4. 先验证网页登录、员工权限、销售退换、现金核对、报表、过期会话和重启持久化；然后执行专属测试环境的31项不变量、容量和备份恢复。定期备份到独立位置，按实际业务确定留存、告警和恢复责任人。
5. 新安装按`compose.yaml`的专用初始化流程取得临时OWNER口令并首登改密；正式运维与测试账户分开。管理员遗失密码按下文受控恢复，不开放公共“重置管理员”接口。

## 七、接上微信开发者工具

先让后端的HTTPS域名可用，再在小程序后台配置对应request合法域名。网络条件参考[微信网络能力文档](https://developers.weixin.qq.com/miniprogram/dev/framework/ability/network.html)。本轮联网工具未能读取微信官方文档正文，因此具体后台入口、主体能力、网络校验和发布要求需在你的后台再次确认。

在源码根目录，把下面两个示例值替换成你的真实信息后构建：

```powershell
node scripts/build-miniprogram.mjs --api https://你的真实域名 --appid wx你的16位编号 --release
```

构建器会拒绝缺失AppID、普通HTTP、IP域名和localhost等不合发布条件的配置。然后在微信开发者工具选择“导入项目”，目录选`apps/miniprogram/build`（这里有project.config.json），填真实AppID，类型为小程序。不要把源码根目录或Web网页的dist当小程序根目录。

工具中先编译，检查14个页面、接口响应、样式、控制台与基础库兼容。用员工账号首次改密后测试业务。开发模拟器允许的本地调试设置不能替代正式包的合法域名校验，不把调试例外带到交付的发布配置。

## 八、真机和体验版验收

1. 用本人微信完成“预览/真机调试”扫码；手机访问`127.0.0.1`指的是手机本身，不能指向电脑后端，真机应使用可访问的HTTPS测试域名。
2. 至少检查iOS和Android的刘海/安全区、键盘、picker、返回、下拉、加载、错误提示和长列表。用弱网/断网模拟“服务器已完成但手机未收到响应”，确认原操作核对后不重复记账。
3. 用两个设备同时编辑同一云端草稿，确认冲突保留内容、保存单据后旧副本不能再次开单。用两个员工验证全员业务共享与他人佣金/成本不可见。
4. 上传后在微信后台生成体验版并添加体验成员，使用测试数据走完退换货补退差价、在途、损坏品、延期、交班和结佣。记录问题和验证结果后再考虑发布。

## 九、正式发布前

按后台填写真实名称、简介、类目、隐私保护说明和运营联系方式，履行适用的备案和审核步骤。可参考`docs/miniprogram/PRIVACY_TEMPLATE.md`，必须填入真实运营主体与联系方式，不能直接把模板当已发布隐私政策。系统无自动微信支付，不能在审核材料里宣称具备该能力。

你以后只需在相应阶段提供AppID和可访问的测试API域名，并亲自完成扫码、实名、条款、购买及上传/发布授权。现在无需补发项目原文件，也无需先注册账号才能查看本轮代码和设计说明。
