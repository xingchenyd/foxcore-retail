# 01 愿景与业务分析

版本 1.0 · 2026-09-27 · 来源：Foxcore Retail A 第 2–3 页，B 第 1–3 页。本文为独立教学实现，与案例企业无官方关联；所有样例人物、价格和业绩均为合成数据。

## 问题与目标

案例 A 描述现场销售员用纸记录，再按日汇总至电子表格。漏记使佣金和库存估计不可靠，跨活动分析商品、员工、展位表现困难。Foxcore 当时已有 17 名销售顾问和超过 28 种商品，且同一周末可能参加多个活动。系统目标是让每笔成交沿 `Event → Booth → Salesperson Shift → Sale → Product Sale` 可追溯，能回答何人、何时、何地、以何价格销售了何商品。

| 现状 AS-IS | 本系统 TO-BE |
|---|---|
| 纸笔记录商品、数量和价格；日终人工转抄 | 销售员登录，关联当前班次，录草稿并准备收款 |
| 未明确收款前的库存状态 | 准备收款冻结金额、占用展位库存；过账后才减少实物 |
| 表格分散，销售归属和提成易争议 | 活动、班次、人员、商品和佣金流水在同一 MariaDB 关联 |
| 退货与更正难以保留历史 | 保留原单，另建退款授权、退货记录和负佣金流水 |

## 角色与范围

- **OWNER**：建立主数据、排班、库存交接、代办成交、退款授权、佣金支付登记和报表核对。
- **SALESPERSON**：查看自己的班次和展位可售量，录入自己的销售与线下收款确认，查看个人佣金。
- 顾客在线下购买，不注册账号。本系统不接入银行卡网关、不保存卡号、不执行资金转账。税率与佣金率由管理员确认，系统内的示例费率不表示法定税率。

## 业务用例

见 [业务用例图](diagrams/business-usecases.puml)。现场员工在已开放活动和已开始班次内创建销售；OWNER 接收、调拨并核对库存，处理退货和结算。所有改变资金、库存或佣金的操作先由服务端验证状态和权限，成功后写审计日志。原始案例要求的九实体在 [数据库设计](04-database.md) 对照。

## 核心业务协同

1. OWNER 建场地、活动、展位、商品和销售员，确认活动税率及员工佣金率。
2. OWNER 排班并把实物从主仓交接到展位；销售员在计划时段内开班。
3. 销售员录入商品、数量和协商单价；系统保存草稿。准备收款时服务器重新核价、验库存并冻结应收金额。
4. 销售员在线下收款并登记现金实收或终端参考号。系统原子写入成交、库存负流水、佣金正流水及审计。响应丢失时使用原幂等键或按单号查询，避免二次收款。
5. OWNER 先取得退款授权，再操作线下退款，随后登记退货；佣金冲回形成负流水。结佣先占用全部未结流水，再登记线下付款。

上述更细的收款、退款和佣金规则是为可运行系统作的 **DEC/EXT** 设计，并非案例原文规定；状态与异常路径见 [SRS](02-SRS.md) 和 [SDD](03-SDD.md)。
