# 本轮实施决策

来源边界：Foxcore A 第 3 页定义业务信息与特定活动商品销量；B 第 3 页提供九实体模型。以下取消、权限、税率、售后和运行策略是本轮项目决策，**不是案例原文的强制细节**。

| 决策 | 实现规则 |
|---|---|
| DEC-FIX-01 | 共享调用器只接受 JSON 字符串/无请求体，用 Headers 合并请求头，合并结果最后写入。所有业务表单使用同一生产函数。 |
| DEC-FIX-02 | OWNER 可取消从未实际开班、无任何销售关联的 PLANNED 班次，包括过期班次；原因、版本、CSRF、幂等均必需。既有 CANCELLED 枚举复用；不新增状态，不删除历史。 |
| DEC-FIX-03A | 活动仅 DRAFT 可完善税率和政策；null/false 可暂存，0 为合法税率。开放后不能经此入口改税。 |
| DEC-FIX-03B | OWNER 修改佣金，只影响之后 sale.prepare 的快照。旧 CHECKOUT/POSTED、退货冲回和结算保持历史口径。0 合法，不新增零额佣金流水。 |
| DEC-FIX-04 | 报表 eventId 与本人权限取交集；POSTED 销售减 POSTED 退货，始终归属原销售活动。CSV 同范围，不引入新的日期含义。 |
| DEC-FIX-05 | 退货目标只可为有效 MAIN，或同原活动内 OPEN、有效的展位和库位。跨活动展位禁止。创建、授权、过账都校验。旧异常目标仍允许走受控取消；不得伪造线下退款事实。 |
| DEC-FIX-06 | 完整门禁只使用新建并核验身份的隔离 Compose 实例；任何环境缺失/阶段失败非零退出。正常运行库不借用，不设生产绕过测试开关。 |
| DEC-FIX-07 | 库存/报表服务器分页并提供 total/hasMore；目录选择通过服务器页分批加载，最多 10000 项，超限显式报错而不交付残缺列表。目录表在已加载集合中分页显示。CSV 单次数据库快照返回最多 10000 个完整分组，超限 413。 |
| DEC-FIX-08 | 保留 SRS UC-01—12 原意，新增 UC-13 认证。修复 SDD 的七个系统特性映射，并更正未实现的“在途/二次确认调拨”文案。原 PDF/图形不冒充同步。 |

## 锁、读取与历史数据

班次创建/开班/关闭/取消先锁父活动，再锁班次/相关员工；与销售、闭场使用共同父活动作为串行点。退货先预读关联，再按数值 ID 排序锁涉及活动（包含旧跨活动目标），继而锁原单、退货及关键对象；写入前重新检查关联及目标。过账按产品 ID 获取相关产品锁，再处理库位余额、流水和佣金。闭场不再要求待入库退货的原销售也属于本活动。

这不是“不会死锁”的保证。保留原有限冲突重试，新的并发 HTTP 用例尚待真实 MariaDB 执行。活动锁有串行化代价，当前没有吞吐基准。

同一分页请求的 COUNT 与 items 使用 REPEATABLE READ 一致视图；不同翻页请求并不共享快照。目录分批读取发现重复 ID 会报错要求刷新，但这不能检测所有并发删除/插入导致的跨页变化。10k 选择器上限是明确的教学系统容量边界，不是无限规模方案。

## 迁移与升级

本次不改变 `001_core.sql`，不新增/删除表，不回填订单，运行账号授权不需要扩大。升级前可执行 `db/preflight-fixes.sql`（只读），人工核对未完成旧退货和关闭活动残余库存。旧授权单若已发生线下退款而未登记，**不能勾选“退款未发生/已撤销”强行取消**；须人工确认真实资金与商品状态，再制定修复。

旧库升级暂未在本环境验证。新建隔离实例与重复初始化/备份恢复由 `verify:full` 提供，但不等同于在任意旧业务数据上的升级证明。
