版本 1.0 · 2026-09-27。测试对象为真实 MariaDB 11.8、Fastify API 与生产构建的 React 页面。测试数据是合成数据，源案例人物及交易未导入。

## 测试策略与环境

| 层级 | 方法 | 验收标准 |
|---|---|---|
| 静态 | 双工作区 TypeScript 严格类型检查、Vite/tsc 生产构建 | 无错误 |
| 计算 | Vitest 金额、小数格式、half-up、幂等键参数 | 所有断言通过 |

本机使用 Node 24、MariaDB 11.8.9（独立本地实例）、Chromium。测试执行命令：`npm run typecheck`、`npm run test:unit`、`npm run test:integration`、`npm run build`、`npm run db:check`、`npm run test:e2e`。浏览器测试需用私有密码文件设置 `TEST_OWNER_PASSWORD_FILE`，文件不能进入发布包。

## 可复现验收用例

| ID | 操作 | 预期 |
|---|---|---|
| AT-01 | 空卷执行 `docker compose up -d --build`，看 `docker compose ps` | db healthy、migrate exited 0、app healthy；首页可打开 |
| AT-02 | 取初始密码，`owner` 登录并更改密码 | 旧会话失效，使用新密码可登录 |
| AT-03 | 建场地、活动、展位、商品、员工，开放活动并排班 | 活动无展位不能开放；销售员只能看自己班次 |
| AT-04 | 主仓收货并确认调拨到展位 | 两端余额及流水相抵，展位可售量正确 |
| AT-05 | 班次开始、录草稿、准备收款、确认成交 | 底价/库存复核；余额与占用变化；成交单号唯一 |
| AT-06 | 同键重试成交；异体复用该键 | 同响应；异体 409；仅一份库存与佣金流水 |
| AT-07 | 同商品最后一件同时准备 20 单 | 恰一单成功，其他拒绝；库存不为负 |
| AT-08 | 两次部分退货、一次超额退货 | 允许范围内成功；超额 409；原单仍保留 |
| AT-09 | 准备佣金、取消或登记支付 | 正负流水合计与结算一致，重复占用拒绝 |
| AT-10 | 销售员请求成本、他人销售、管理接口 | 不泄露批发成本，跨人查询 404/403 |
| AT-11 | 查看事件/商品/员工报表和 CSV | 只计已过账销售减已过账退货，CSV 限 OWNER |
| AT-12 | 重启容器、再次登录并跑不变量检查 | 单据持久，差异均为 0 |
| AT-13 | 按文档备份至本机、恢复到独立空卷 | 账本及不变量一致；不覆盖生产卷 |

## 已知边界与后续验收

本系统登记线下收款、退款和佣金支付依据，不与资金渠道自动核对。税率和佣金率由管理员填写并确认。管理员报表中的毛利是商品标准成本估计。销售界面每页 20 笔，商品/活动等选择器最多载入 100 项；长期高交易量运营仍应扩充全模块分页、完成 10000 条规模性能测试和真实 Docker 跨主机演练。以上不应被解释为已经测试通过。
