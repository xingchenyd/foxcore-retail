# Foxcore 工作人员微信小程序

2026-10-26。交付分支 `codex/staff-miniprogram-20261026`，基于已合并网页改进的 main `744c36ac67abb28963f32077c219fbb4047d28c4`。本轮小程序代码不合并 main。

这是原生 WXML / WXSS / TypeScript 小程序，复用现有 Fastify API 和 MariaDB，包含 13 个页面。没有将网页嵌入 web-view，也没有创建第二份业务库。数据库迁移未改动，仍为 25 张业务表与 1 张迁移表。

## 编译与导入

需要 Node 24；首次 `npm ci`。开发者工具无需构建 npm：产物仅为原生 JS、WXML、WXSS、JSON 与图标。

```powershell
npm run mini:typecheck
# 本机适配预览，不用于手机正式运行：
npm run mini:build -- --api http://127.0.0.1:3000 --development
# 实际微信联调 / 发布配置；替换成自己真实的 API 和公开 AppID：
npm run mini:build -- --api https://api.example.com --appid wx0123456789abcdef --release
```

导入 **`apps/miniprogram/build`**，其中有 `project.config.json` 和 `miniprogram/`。不应直接把 `src/` 当作运行包。默认构建在 API 未配置时可以检查代码结构，登录会明确提示联系管理员；默认 `touristappid` 不代表可上传或真机可用。

`--release` 会拒绝未设置的 API、HTTP、回环地址和占位 AppID。它只表示构建参数检查通过，不能验证域名解析、TLS证书、微信合法域名、账号权限、网络可达性或微信审核。

AppID 是公开标识；不要把 AppSecret、商户密钥、业务口令、数据库连接或用户会话写进代码。这个版本无需 AppSecret。`project.private.config.json`、`build/`、`dist/` 不入 Git。

后端与网页是同一服务。按原部署文档配置数据库、HTTPS反向代理、`PUBLIC_ORIGIN` 与 `COOKIE_SECURE`。网页 Cookie 行为保持；小程序不需要为原生请求新增通配 CORS，也不应放宽数据库授权。小程序后台配置与 API 一致的 request 合法域名。手机上的 127.0.0.1 是手机自己，不是这台电脑。

## 业务操作

1. 管理员先在网页配置活动、展位、商品、员工、税率/佣金与班次。工作人员登录小程序，首次修改初始密码后重登。
2. 工作台开班；管理员在库存页完成主仓收货与实物调拨，销售员可查看自己展位可售量。
3. 销售：选进行中班次 → 商品及成交价 → 保存草稿 → 详情核价占库 → 核对线下收款 → 确认过账。金额预估只辅助录入，税额、库存和佣金以服务端快照为准。
4. 退货：管理员从已成交原单进入，勾选行、数量、可售/损坏、归属库位与原因；保存后授权核价，再登记实际退款及参考号。超退在服务端拒绝。
5. 佣金：销售员看本人流水与结算构成；管理员准备未结流水、核对线下付款后登记参考号。取消待付款结算须核对线下付款未执行或已撤销。
6. 业务完毕处理待办再关班。管理网页保留复杂配置、审计与完整经营报表。

列表以服务器分页加载，搜索/状态筛选仅作用于已经加载的记录，页面明确显示数量与范围。选择器完整分页读取，超过 10000 项明确报错。工作台只展示最近各 20 条班次/销售的任务信息，其计数不是全部经营指标。

## 弱网与恢复

- 录入销售时可保存本机草稿；正式成交、退款、盘点和结算必须在线。
- 写请求发送前持久保存 UUID、原请求内容及所属用户；重复点击有同步提交锁；同一操作响应丢失后保持原幂等键。
- 网络中断或服务端 5xx 不当作业务失败；提示结果待核对。切换到「我的 → 待核对操作 → 继续核对」，使用原内容、原编号重试，禁止改变原待核对请求体。
- 该入口可跨页面和进程重启继续使用。切换账户只显示当前用户自己的待核对请求；退出不会删除未核对的事实记录。
- 任何情况下都不自动重做线下收付款，不自动释放已准备销售的库存。若原请求业务条件已变化，由服务端冲突响应及管理员核对处理。
- 会话仍为服务端随机会话，数据库只保存 token 哈希；12 小时绝对超时、30 分钟空闲超时；停用、改密与退出沿用现有撤销逻辑。

## 新增接口与兼容

| 接口 | 作用 |
|---|---|
| `POST /api/v1/auth/mini/login` | 校验现有员工口令，返回 bearer / csrf / user，不设置 Cookie |
| `POST /api/v1/sales/:id/edit` | 微信请求适配；与原 PATCH 共用同一事务、版本和幂等实现 |
| `GET /api/v1/commissions/settlements/:id` | 返回结算与来源行；销售员只能查看本人 |

业务 API 接受 `Authorization: Bearer …`；写请求继续检查 `X-CSRF-Token`。同一请求同时带业务 Cookie 和 bearer 时拒绝，避免身份选择歧义。旧网页登录不会返回 bearer，原 Cookie 路径保持。详细合同见 `openapi-extension.json`。

## 验证与尚需用户操作

本次实测结果见 `verification.json`；原 `docs/course-review` 是 2026-10-24 的历史审查快照。

`npm run verify:static` 会检查原服务端、网页和小程序 TypeScript、单元/纯逻辑与生产构建。真实数据库测试必须使用专用实例和私有测试凭据；`tests/integration/miniprogram.test.ts` 覆盖跨端数据与权限；`miniprogram-pages.test.ts` 执行真实 Page 控制器及请求层，不能把它等同于微信引擎测试。

`npm run mini:preview` 启动仅监听 127.0.0.1 的开发适配器，读取实际 WXML 和编译后 Page。它是开发与布局检查辅助，页面固定注明“非微信真机”，不作为生产网站发布。开发适配器只能代理指定的回环 API，不内置账户或演示凭据。

要进入微信编译/扫码体验，需要用户准备 AppID，在微信开发者工具完成扫码登录，并配置可访问的 HTTPS API 与后台合法域名。然后验证 iOS/Android、键盘与弹窗、切后台恢复、存储持久性、请求超时、Cookie/bearer交互及所有业务链，再上传体验版。涉及隐私接口时按实际能力填写指引。账号、认证、审核与发布需按平台流程由账号持有人操作。

目前尚无微信开发者工具编译/真机测试、微信体验版上传、正式审核、公网部署或 Docker 备份恢复的通过证据。

## 交付校验

`SHA256SUMS` 按 Git 归档字节计算：常规文本使用 LF，历史已提交的 CRLF 图源保留原样，二进制不转换。完整源码 ZIP 使用 Git 提交归档，逐文件核对清单。Windows 工作区若自动转为 CRLF，直接按原始字节校验会不同，应规范化文本换行后校验。图源与两张架构/恢复图位于 `diagrams/`，离线交付手册为 `index.html`。
